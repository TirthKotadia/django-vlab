Theory

Static files in Django are files that do not change dynamically per request — CSS, JavaScript, Images, Fonts. They are different from Media files which are user-uploaded (e.g., profile pictures).

Unlike plain HTML where you write <link href="style.css">, Django does not serve static files automatically. You must explicitly configure where they are stored and how to link them. The browser request /static/css/style.css is only resolved if STATIC_URL and template tags are correct.

Key Configuration

1. settings.py

# vlab_project/settings.py
STATIC_URL = '/static/' # URL prefix for browser
STATICFILES_DIRS = [BASE_DIR / 'static'] # where Django searches
STATIC_ROOT = BASE_DIR / 'staticfiles' # for collectstatic

2. Template Tags — every template that uses static must load the library:

<!-- top of template.html -->
{% templatetag openblock %} load static {% templatetag closeblock %}

<!-- use static tag -->
<link rel="stylesheet" href="{% templatetag openblock %} static 'css/style.css' {% templatetag closeblock %}">
<img src="{% templatetag openblock %} static 'images/logo.png' {% templatetag closeblock %}">

{% templatetag openblock %} static 'css/style.css' {% templatetag closeblock %} is replaced at runtime with /static/css/style.css using the value of STATIC_URL. If either side is misconfigured, the browser shows 404 Not Found.

Development vs Production

  • Development: python manage.py runserver automatically serves files from STATICFILES_DIRS when DEBUG=True.
  • Production: Run python manage.py collectstatic to collect all static files into STATIC_ROOT, then serve via Nginx or WhiteNoise.
